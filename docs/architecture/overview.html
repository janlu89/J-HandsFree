Component overview

Everything runs in one Android process. The YouTube page runs inside a WebView. Injected scripts act as sensors and actuators: they observe the player and run its commands. The Skip button is pressed with a native tap, and the WebView itself reports its window as visible, so audio continues in the background. The C# code makes every decision.

Why

The scripts are thin adapters. All the logic (when to skip, when to release background playback, how to react to buttons) lives in C# in the use case layer and is tested with xUnit without a phone or an emulator. When YouTube changes its page, one adapter changes, not the logic.

Solution projects

Clean Architecture adapted to mobile. Dependencies point inwards only, and Android code stays in one edge project.

Why

Domain, UseCases and PlayerProtocol are plain net10.0, so the state machine, the skip policy and the message contract run in tests on any CI runner in milliseconds. The use case layer is named UseCases because a namespace called Application would collide with MAUI's Application class.

Automatic ad skip flow

The script watches the player with a MutationObserver. It blocks nothing: it waits for YouTube to show the Skip button and reports where it is, and the app taps it like a finger.

Background playback flow

Two things keep audio alive. The Media3 playback service keeps the process running. KeepVisibleWebView tells Chromium that its window is visible, so the page's media is never suspended.

Playback states

PlaybackState lives in the Domain. Every player event is a transition, so edge cases such as an ad in the middle of a playlist or a long pause become tests instead of bugs.

Messages, ports and adapters

Inbound traffic is dispatched in process by Mediator: the bridge publishes notifications, the media session and view models send commands and queries. Outbound calls go through ports that Infrastructure implements, except the visibility switch, which lives in Mobile next to the view it controls. MauiProgram wires everything together.

Why a mediator, and still no CQRS

One player event must reach several coordinators, every message should be logged in one place, and a failing handler must never reach the WebView. Mediator by Martin Othamar covers this with notifications, a pipeline behaviour and a custom publisher. It is MIT licensed like this repository and generates its code at compile time, so nothing breaks when Android Release builds trim unused code. CQRS stays out: there is one model and one small store, so separate read and write models would add ceremony without benefit.

Implementation phases

Ordered to remove the risks that could stop the project first, then built from the inside out.

  1. Feasibility spike done

    Throwaway app: sign-in, background audio with another app in front, Skip by native tap, message round trip, Activity survival. Every assumption has a result; see Phase 0 progress and the spike report.

    Done when: every assumption is confirmed or has a chosen fallback, written in a spike report.
  2. Foundations next

    Repository, rulesets, solution, test projects, scripts project, DI wiring, CI, signing, first release v0.1.0.

    Done when: a merge into master publishes a signed APK that Obtainium installs.
  3. Domain and use cases

    Value objects, the state machine, policies, contracts, ports and the three coordinators, written test first.

    Done when: 90 percent coverage and no platform references in either project.
  4. Player and bridge

    PlayerPage, script injection, protocol translator, bridge, selectors with snapshot tests, sign-in.

    Done when: play, pause and next work from C# commands on the phone.
  5. Background playback

    KeepVisibleWebView, Media3 service and player facade, permissions, system controls, idle prompt, pause timeout.

    Done when: a one-hour field test in the car passes without touching the phone.
  6. Automatic ad skip

    Ad watcher, skip coordinator with the native tap, settings, skip statistics, diagnostics and health warning.

    Done when: 20 consecutive skippable ads are skipped within one second each.
  7. Hands-free comfort

    Drive mode, sleep timer, home screen shortcuts, seek buttons, resume last session, remote selectors, optional sponsor segment skipping.

    Done when: each selected feature meets its acceptance criteria.
  8. Release 1.0

    Icon, about screen with attributions, screenshots, v1.0.0, install guide for friends.

    Done when: a friend installs it from the README without help.
  9. .NET 11 migration

    Starts after the November release on its own branch: frameworks, packages, CoreCLR on device, CI, field test.

    Done when: all checks are green on .NET 11 and the field test passes.
